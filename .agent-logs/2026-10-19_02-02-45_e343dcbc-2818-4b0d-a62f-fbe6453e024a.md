## Cause

None of my effects were `async`, and none returned a Promise on purpose. The bug was three effects written as one-line arrow functions, so they returned whatever their last call returned:

- `components/AskPanel.tsx:95` — `useEffect(() => endRef.current?.scrollIntoView(...), [msgs])`
- `components/meeting/TranscriptTab.tsx:84` — `useEffect(() => setDraft(raw), ...)`
- `components/meeting/TranscriptTab.tsx:264` — `useEffect(() => setCurrent(0), ...)`

In stock Chromium, `scrollIntoView()` returns `undefined`, which is why my earlier checks passed. A smooth-scroll polyfill or browser extension can make it return a Promise. React then treats that Promise as the cleanup function, which gives the "useEffect must not return anything besides a function" warning and then `destroy is not a function`, and the tree unmounts.

I couldn't reproduce it in stock Chromium, so I simulated that condition. Before the fix, the home page logged the same errors you quoted. The earlier dev-server log also had those errors from a real browser.

## Fix

- **The three effects:** all now use block bodies, so they return nothing.
- **Audit of every effect in `app/`, `components/` and `lib/`:** no `async` effects and none returning a Promise. The one `() => () => store.destroy()` correctly returns a function, so I left it.
